# Exact-Statement signing migration (unreleased)

The existing private CI package now prepares exact in-toto v1 signing for rollout-gate's enforcing contract. It consumes the real nightly emitter's canonical `evidence-payload-*.json` files and writes `sigstore-dsse-rows/v1`. The published J-Rig CLI and its Node 20 runtime contract are unchanged; its existing cosign attest-blob output remains incompatible with the new strict Action until migrated separately.

The private package requires Node 22.22.2+, 24.15+ or 26+. The exact `@sigstore/sign` 5.1.0 engine requirement and DSSE builder API are documented in [official package source](https://github.com/sigstore/sigstore-js/blob/4576519/packages/sign/package.json) and [builder source](https://github.com/sigstore/sigstore-js/blob/4576519/packages/sign/src/bundler/dsse.ts). The builder owns DSSE pre-auth encoding and bundle construction; Node crypto performs only the P-256 signing primitive for an externally enrolled private key.

Private mode takes an explicit PEM path and key hint and creates no public-log requests. It does not auto-enroll its public key in the consumer. A protected caller must supply the corresponding trusted key policy independently.

Public mode requires explicit `--keyless`, runs the existing vendored DNSSEC and CAA preflights with production defaults before requesting credentials, and uses official FulcioSigner, CIContextProvider and RekorWitness. The adapter requires a returned inclusion proof and signed checkpoint before writing the output. A promise-only response fails; an upstream entry may already exist, so this failure is not safe to interpret as proof that no public write occurred. The consumer still independently verifies signatures, identity and every proof against authenticated trust roots.

The draft nightly workflow adds an explicit default-false migration input. Scheduled runs and ordinary dispatches retain existing metadata signing and dashboard inputs. Enabling the input performs public writes and is held for reviewed production rollout; no such execution has occurred. Signed rows and original payloads are retained for 14 days in an immutable SHA/run/attempt-named Actions artifact, with file digests and workflow/source provenance. An always-run capture preserves partial artifacts after a signing failure and explicitly labels incomplete trials; it never turns a failed signing step into success. Pinning the Node version to 22.23.1 satisfies the existing private package's new dependency contract.

Offline qualification uses real `buildRows` and `writeEmit` outputs, ephemeral synthetic keys, the real signer and the separately built enforcing Action. Run from this directory after normal standalone installation:

```sh
ROLLOUT_GATE_DIST=/absolute/path/to/reviewed/intent-rollout-gate/dist/index.js pnpm run test:signing
```

The test process denies network connections, and its Action child inherits that guard. Public factory tests inspect preflight order and construction only; they do not claim a public signing integration ran. Tampered payloads must block at the built Action entry. The canonical standalone install and corrected typecheck plus seventeen offline tests passed against Action commit 9e0cfa3 and dist SHA256 bd9287783b3e685829e1a20b8508a5f185c89cd340d9d4e7285a42dbbf2dd047. The initial attempt failed test type inference before tests; corrected seven-case interoperability passed, then twelve cases passed after adding real workflow provenance success/failure controls, followed by seventeen cases including size boundaries. All receipts are retained. The Lint, Test and nightly jobs hash both root and standalone lockfiles for their existing pnpm cache, following [setup-node cache-dependency-path semantics](https://github.com/actions/setup-node#caching-global-packages-data). No cache timing improvement is claimed. The existing PR Test job now installs this already-present standalone package, sparse-checks out that immutable consumer fixture without persisting credentials, verifies its digest, and runs these gates. This is a test fixture pin, not production consumer migration.

Remaining delivery includes reviewed exact-head checks, producer/consumer immutable pin updates, explicit trust enrollment where needed, and production rollout approval. The old dashboard metadata signature path remains operational throughout preparation. No public Rekor, DNS, secret, release-tag or production trust changes are part of local testing.

## Consumer size parity

The consumer caps each complete serialized Sigstore row at 4 MiB and the raw container at 16 MiB. Before any builder request, the producer checks deterministic base64 plus minimum mandatory-envelope/container byte lower bounds for all rows and the aggregate. Passing this preflight cannot predict variable certificate, signature or proof overhead. Each actual returned row is serialized and checked; the aggregate budget is updated immediately, including commas and the final newline, before another signing request is allowed. The final artifact is checked again before atomic output. A late service-overhead rejection can follow a public write already made for that row; incomplete trial capture preserves available artifacts without declaring success.

Boundary controls cover rejection before public preflight, aggregate expansion before the first builder call, exact row/container equality, oversized returned metadata, and cessation of additional signing after actual aggregate overflow. The large returned-metadata controls simulate response size; they do not claim those artificial key hints are enrolled consumer identities. The corrected size candidate passed all 17 native cases and the full workspace check (170 files, 2,629 passed and one existing skip). The final workspace chain took 526.186 seconds under a 4 CPU / 4 GiB cap with one Vitest worker. The initial final chain stopped on a documentation-only blank line after native tests passed; the resumed chain passed documentation lint, actionlint and all workspace gates without repeating unchanged native tests. Earlier failed and pre-size-fix receipts remain separate.
